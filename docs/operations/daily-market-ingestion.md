# ورود روزانه داده بازار و تحویل به دستیاران

نسخه اول این ابزار فایل محلی Excel یا CSV را دریافت، اعتبارسنجی و نرمال‌سازی می‌کند.
سه بازار پوشه، تنظیمات و گزارش جدا دارند؛ این ابزار به کارگزار یا شبکه وصل نمی‌شود
و خروجی آن توصیه خریدوفروش نیست.

## نصب و اجرای شاخه

تا پیش از ادغام، این قابلیت فقط در شاخه زیر موجود است. فرمان‌ها را از ریشه مخزن
و در محیط مجازی فعال اجرا کنید.

```bash
git fetch origin
git switch feat/multi-market-data-pipeline
python -m pip install -e ".[dev,excel]"
```

اگر محیط مجازی ندارید، ابتدا `python -m venv .venv` را اجرا کنید.
در ویندوز آن را با `.venv\Scripts\activate` و در لینوکس/macOS با
`source .venv/bin/activate` فعال کنید.

## قرارداد فایل

- **Excel:** فقط `.xlsx`، با شیت دقیقاً به نام `ohlcv`؛ `.xls`، ماکرو و فایل رمزدار
  پشتیبانی نمی‌شوند. سطر نخست نام ستون‌ها و سطرهای بعدی مشاهده‌های واقعی بازار است.
- **CSV:** متن UTF-8 یا UTF-8-BOM، جداکننده ویرگول؛ قالب خالی در
  `examples/manual-market/ohlcv-header.csv` قرار دارد. این قالب داده بازار ندارد.
- **ستون‌های ضروری:** `timestamp,symbol,open,high,low,close,volume`.
- **ستون‌های اختیاری:** `market,timeframe,currency,venue,volume_unit`؛ اگر وجود دارند
  باید در همه سطرها دقیقاً با گزینه‌های اجرای فرمان برابر باشند. ستون ناشناخته رد
  می‌شود تا داده به‌طور خاموش نادیده گرفته نشود.
- **زمان:** رشته متنی ISO 8601 با offset، مانند قالب
  `YYYY-MM-DDTHH:MM:SS+03:30` یا پسوند `Z`؛ زمان پس از ورود به UTC تبدیل می‌شود.
  ستون Excel را Text قرار دهید. تاریخ شمسی، تاریخ صرف بدون ساعت/offset و سلول
  تاریخ بومی Excel رد می‌شوند؛ timezone حدس زده نمی‌شود.
- **قیمت و حجم:** اعداد متناهی، قیمت مثبت، حجم غیرمنفی و OHLC سازگار؛ مقدار خالی
  با صفر یا قیمت قبلی جایگزین نمی‌شود. فرمول Excel/CSV، از جمله نتیجه cacheشده،
  به‌عنوان داده معتبر استفاده نمی‌شود.
- **ردیف‌ها:** هر نماد در یک فایل باید زمان صعودی و بدون زمان تکراری داشته باشد.
  چند نماد مجاز است، ولی فایل واحد فقط یک بازار، venue، ارز و timeframe دارد.
- **حدود:** فایل حداکثر ۲۰ MiB، محتوای بازشده XLSX حداکثر ۱۰۰ MiB، حداکثر
  ۱۰۰٬۰۰۰ سطر داده و ۳۲ ستون؛ نسخه اول فایل را یکجا در حافظه پردازش می‌کند.

برچسب timestamp باید از منبع واقعی صادرات داده بیاید. قرارداد تاریخ روزانه
ارائه‌دهنده، تعدیل قیمت‌ها و واحدها را در منبع خود بررسی کنید؛ ابزار نمی‌تواند
درستی اقتصادی یا رسمی‌بودن داده‌ای را که دستی اعلام کرده‌اید اثبات کند.

## اجرای دستی با تفکیک سه بازار

گزینه‌های `source`، `venue`، `currency` و `volume-unit` اجباری‌اند. نام فایل‌ها
در دستورها نمونه مسیر هستند و باید فایل واقعی خودتان را جای آن‌ها بگذارید.

### بورس ایران

```bash
arya ingest-market-file --file data/inbox/iran_equity/market.xlsx \
  --market iran_equity --source manual-tsetmc-export --venue TSE \
  --currency IRR --volume-unit shares --timeframe 1d \
  --root data/market_pipeline
```

اگر منبع صریحاً تومان است، `--currency IRT` را انتخاب کنید؛ تبدیل خودکار انجام
نمی‌شود. `iran_equity` در مدل مشترک موجود به `stock` نگاشت می‌شود و قراردادهای
فعلی Provider تغییر نام داده نمی‌شوند.

### رمز ارز

```bash
arya ingest-market-file --file data/inbox/crypto/market.xlsx \
  --market crypto --source manual-exchange-export --venue YOUR_EXCHANGE \
  --currency USDT --volume-unit base_asset --timeframe 1h \
  --root data/market_pipeline
```

venue را با نام صرافی واقعی خود جایگزین کنید. حجم باید واقعاً بر حسب دارایی
پایه باشد؛ حجم quote را بدون تبدیل تأییدشده به این ستون منتقل نکنید.
این قابلیت صرفاً ورود فایل است و Adapter زنده صرافی فعال نمی‌کند.

### فارکس

```bash
arya ingest-market-file --file data/inbox/forex/market.csv \
  --market forex --source manual-broker-export --venue YOUR_DATA_SOURCE \
  --currency USD --volume-unit ticks --timeframe 1h \
  --root data/market_pipeline
```

اگر منبع tick volume می‌دهد، از `ticks` استفاده کنید؛ tick count با حجم واقعی
معاملات یکی فرض نمی‌شود. برای منابع دارای حجم واقعی دارایی پایه، `base_asset`
مجاز است. جفت‌ارزهایی با ارز مظنه متفاوت را در فایل‌های مجزا وارد کنید.

فرمان معادل مستقل از نصب entry point به شکل زیر است؛ همه گزینه‌ها یکسان‌اند.

```bash
python -m arya.data_ingestion --help
```

## پوشه مشترک کاربر و دستیاران

ساختار پیشنهادی ورودی را روی دستگاه اجرای پروژه ایجاد کنید. پوشه ورودی می‌تواند
یک پوشه محلی یا پوشه‌ای باشد که قبلاً با Google Drive همگام شده است.

```text
data/inbox/
  iran_equity/
  crypto/
  forex/
data/market_pipeline/
  iran_equity/
    runs/<run_id>/
      input.xlsx                 # یا input.csv؛ نسخه دقیق ورودی
      manifest.json
      normalized.json
      report.json
      report.md
      agent_outputs/
        data_quality.json
        technical.json
        fundamental.json
        market_flow.json
        risk.json
        synthesis.json
    rejected/<run_id>/
      input.xlsx
      manifest.json
  crypto/
  forex/
```

خروجی هر بازار و اجرای آن جداست. برای سادگی انتشار اتمیک، اصل بایگانی‌شده،
manifest، داده normalized و گزارش در همان پوشه run نگه‌داری می‌شوند، نه
پوشه‌های جداگانه‌ای که ممکن است نیمه‌کاره و ناسازگار دیده شوند.
فایل اصلی کاربر هرگز حذف، جابه‌جا یا بازنویسی نمی‌شود؛ پوشه rejected نیز کپی
و علت رد را نگه می‌دارد. خطاهای پیش از دریافت امن فایل، مانند فایل مفقود،
پسوند نامجاز یا اندازه بیش از حد، فقط در خطای CLI ثبت می‌شوند.

### بررسی یک‌باره پوشه

```bash
python -m arya.data_ingestion --inbox data/inbox/iran_equity \
  --market iran_equity --source manual-tsetmc-export --venue TSE \
  --currency IRR --volume-unit shares --root data/market_pipeline \
  --settle-seconds 30
```

این دستور یک بار پوشه را بررسی می‌کند و پایان می‌یابد؛ watcher دائمی، job ابری
یا اجرای زمان‌بندی‌شده نصب نمی‌کند. فقط فایل‌های مجاز در سطح همان پوشه، با سن
بیش از حد تعیین‌شده و نام غیرموقت بررسی می‌شوند؛ symlink و نام‌های شروع‌شونده
با `~$` یا نقطه پردازش نمی‌شوند.

هنگام بارگذاری ابتدا نام موقت بدهید و پس از پایان انتقال، فایل را به نام نهایی
تغییر دهید. عمر فایل به‌تنهایی پایان دانلود cloud را اثبات نمی‌کند؛ فایل نباید
در زمان پردازش در حال ویرایش باشد. ورودی هر پوشه باید source/venue/ارز یکسان
داشته باشد؛ در غیر این صورت پوشه‌های بیشتری جدا کنید.

برای اجرای روزانه، اپراتور می‌تواند همین فرمان را در Task Scheduler ویندوز یا
cron دستگاه خود ثبت کند؛ در این تغییر هیچ زمان‌بندی‌ای فعال نشده است.
خروجی root را روی دیسک محلی قابل اعتماد نگه دارید، نه مقصدی با چند نویسنده
cloud. فایل‌ها و خروجی‌های واقعی عمداً در `.gitignore` قرار دارند.

## manifest، تکرار و خرابی

manifest شامل hash SHA-256 اصل فایل، hash داده normalized، نسخه schema و pipeline،
context بازار، زمان دریافت، بازه داده و تعداد نماد/سطر است. شناسه اجرا از hash فایل
و context ساخته می‌شود؛ تغییر ارز یا venue باعث اجرای مجزا می‌شود.

ورود دوباره همان ورودی با همان context خروجی `DUPLICATE` می‌دهد و گزارش تاریخی
قبلی را بازنویسی نمی‌کند. CLI در این حالت تازگی را نسبت به زمان اجرای جدید
دوباره محاسبه می‌کند؛ `generated_at_utc` گزارش ذخیره‌شده همچنان زمان قدیمی است.
گزارش‌ها تاریخچه snapshot هستند، نه نمای زنده وضعیت امروز.

فقط run نهایی را مصرف کنید؛ پوشه‌های `.pending-*` خروجی تأییدشده نیستند.
انتشار در یک filesystem با rename پوشه انجام می‌شود و یک قفل محلی مانع نویسنده
هم‌زمان همکار می‌شود. اگر worker با قطع برق متوقف شد، قفل ممکن است باقی بماند؛
قبل از حذف دستی `.ingest.lock` مطمئن شوید هیچ worker فعالی وجود ندارد.
این سازوکار جایگزین قفل توزیع‌شده یا مقابله با کاربران مخرب روی دیسک مشترک نیست.

## تازگی، ریسک و خروجی دستیاران

- **کیفیت ساختاری:** قبولی schema و OHLCV به معنی رسمی‌بودن، کامل‌بودن یا
  تازه‌بودن داده نیست؛ `source_trust` همیشه `UNVERIFIED` می‌ماند.
- **تازگی:** پیش‌فرض `UNKNOWN` است. با `--max-age-hours N` یک حد ساعت انتخابی
  اپراتور اعمال می‌شود؛ این حد تقویم بورس، تعطیلات یا سشن فارکس را نمی‌شناسد.
  وضعیت `WITHIN_AGE_LIMIT` ادعای رسمی «بازار باز/داده زنده» نیست.
- **ریسک:** تاریخ آینده یا نماد قدیمی باعث `BLOCK` می‌شود. در سایر حالت‌ها
  وضعیت `UNASSESSED` است، نه `PASS`؛ هیچ مجوز معامله‌ای تولید نمی‌شود.
- **تکنیکال:** در این نسخه فقط قیمت آخر و کمینه/بیشینه بازه به‌صورت توصیفی
  گزارش می‌شود، نه استراتژی یا پیش‌بینی. داده کم نباید با تحلیل قطعی جایگزین شود.
- **بنیادی و جریان پول:** ورودی لازم ندارند و صریحاً `NOT_AVAILABLE` هستند؛
  مرحله‌ای که داده ندارد امتیاز یا ادعای تحلیل ساختگی تولید نمی‌کند.
- **دستیاران:** فایل‌های `agent_outputs` خروجی مرحله‌های deterministic هستند،
  نه چند ایجنت مستقل مستقرشده. دستیاران بعدی باید `run_id`، hash و context را
  همراه خروجی حفظ کنند و فقط از داده normalized استفاده کنند.

## وضعیت Drive و کار بعدی

این ابزار Google Drive API را فراخوانی نمی‌کند و در این مرحله هیچ پوشه، سند،
اتوماسیون یا حافظه ابری ایجاد نشده است. برای شروع، کاربر می‌تواند فایل را دستی
دریافت و در inbox محلی قرار دهد؛ اتصال خودکار بعداً با انتخاب پوشه، سطح دسترسی،
manifest فایل cloud و مجوز جداگانه انجام می‌شود.

مرحله بعد، پس از بازبینی مالک، تعریف قرارداد واقعی بنیادی/جریان پول، تقویم هر
بازار و اتصال تحلیلی معتبر به normalized است. از اتصال مستقیم این نسخه به
سفارش‌گذاری یا معرفی آن به‌عنوان «سامانه معاملاتی آماده» خودداری کنید.
