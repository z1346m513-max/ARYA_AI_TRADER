## دلیل

کاربر درخواست کرد مخازن GitHub که می‌توانند ARYA را از نظر نرم‌افزار، هوشمندسازی و تحلیل ارتقا دهند بررسی و بهره‌برداری مجاز اعمال شود. پروژه دارای مرزهای provider، پایپ‌لاین تحلیل و SQLite است؛ ارزش کم‌ریسک و فوری‌تر، جلوگیری از ورود OHLCV ناسازگار به تحلیل و ایجاد پیوند قابل‌ردیابی بین داده و Recommendation است.

## شواهد و ارزیابی منابع

- ده پروژه بررسی شدند: OpenBB, FinanceDataReader, Microsoft Qlib, backtesting.py, QuantStats, vectorbt, Dagster, SHAP, Great Expectations و OpenLineage. گزارش شامل URLهای canonical و license، تناسب، ریسک و تصمیم هر مورد است.
- هیچ‌یک از شواهد مورد بررسی پشتیبانی زنده/رسمی TSETMC یا پوشش کامل بازار ایران را اثبات نمی‌کند؛ از آن‌ها به‌عنوان feed بورسی استفاده نشده است.
- مجوزهای مهم: MIT (FinanceDataReader/Qlib/SHAP)، Apache-2.0 (QuantStats/Dagster/Great Expectations/OpenLineage)، AGPL-3.0 (backtesting.py)، Apache-2.0 همراه Commons Clause (vectorbt). در OpenBB، مجوز ریشه AGPL و ادعای README/package مبنی بر Apache ناسازگار است؛ استفاده از کد آن تا رفع تعارض متوقف است.
- هیچ سورس، binary، dependency، dataset یا کد نمونه از مخازن نامزد به ARYA کپی/نصب نشده است. پیاده‌سازی این CR کد تازه و native است؛ انتخاب آن از بررسی الگوهای Data Quality/Lineage الهام گرفته است.
- شواهد دقیق و محدودیت‌های license/IP در گزارش ممیزی ثبت شده‌اند. این بررسی جایگزین بازبینی حقوقی کامل یا بررسی license هر dependency در تغییرات آینده نیست.

## تغییرات

1. `arya.data_quality.validate_ohlcv_series` checks ساختاری برای سری خالی، timestamp غیرمعتبر/نامرتب/تکراری/دارای timezone ناسازگار، قیمت‌های غیرمتناهی یا غیرمثبت، حجم منفی و OHLC ناسازگار ارائه می‌کند.
2. `AryaApp` پیش از تحلیل، فیلتر یا استراتژی، داده را از gate عبور می‌دهد. هر batch معتبر یا مردودشده در `data_quality_runs` ثبت می‌شود: provider، ابزار/بازار/timeframe، زمان دریافت برنامه به UTC، تعداد و بازهٔ timestamp، هش SHA-256 دادهٔ نرمال‌شده، وضعیت و issueها.
3. `Recommendation.data_quality_run_id` رکورد provenance دادهٔ ورودی را به خروجی نهایی پیوند می‌دهد.
4. CLI در صورت شکست gate پیام فارسی می‌دهد و با exit code 2 متوقف می‌شود.
5. راهنمای عملیات و این گزارش ممیزی افزوده/به‌روزرسانی شدند.

## محدودیت‌ها و ریسک

- `retrieved_at_utc` زمان ثبت/دریافت محلی برنامه است و نه timestamp رسمی منبع؛ freshness، session calendar، تعطیلات، توقف نماد، کامل‌بودن OHLCV یا صحت مالی در این CR احراز نشده‌اند.
- این checks قوانین عمومی ساختاری‌اند؛ قیمت مثبت و ترتیب زمانی به‌تنهایی نشان‌دهندهٔ صحت معامله، منبع رسمی یا قابل‌اعتماد بودن سیگنال نیست.
- خطاهای داده fail-closed هستند و می‌توانند تحلیل را متوقف کنند؛ مشکل upstream باید در issueهای ذخیره‌شده قابل‌پیگیری باشد.
- افزودن جدول SQLite با `CREATE TABLE IF NOT EXISTS` انجام می‌شود؛ داده‌های قبلی و جدول OHLCV تغییر داده یا migrate نشده‌اند.
- هیچ backtester، fee/slippage model، تقویم معاملاتی ایران، point-in-time fundamentals یا جلوگیری از survivorship bias در این change اضافه نشده است.
