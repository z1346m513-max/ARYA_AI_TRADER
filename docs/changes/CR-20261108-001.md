## Evidence and design distinction

- Baseline provider and `docs/operations/live-data-and-drive-sync.md` section 5
  already expose first-result fallback and use of local time as source time.
  Deterministic regression fixtures verify their removal; no claim of live API
  verification is made.
- Existing `arya.data_quality.validate_ohlcv_series` provides structural invariants
  and is reused rather than duplicating analytical logic.
- This manual-file schema is an ARYA-owned, versioned design requested by the
  owner, not a claim about TSETMC, a broker or an exchange export.
- Python CSV contract: https://docs.python.org/3/library/csv.html
  (accessed 2026-11-08). CSV cells are literal text; width/header checks are explicit.
- openpyxl workbook contract:
  https://openpyxl.readthedocs.io/en/stable/tutorial.html
  (accessed 2026-11-08). `read_only=True`, `data_only=False`; formula strings are
  rejected, not replaced by cached results.
- Dependency/security guidance:
  https://openpyxl.readthedocs.io/en/stable/
  (`defusedxml` required for XML input; workbook size and expanded ZIP size bounded).

## Scope and compatibility

- Add isolated `arya.data_ingestion`, with `arya ingest-market-file` and module CLI.
- Existing models keep market `stock`; manual-files UI uses `iran_equity` and
  explicitly maps it to `stock` for existing quality validation.
- Context includes market, source, venue, currency, timeframe and volume unit.
  There is no implicit Rial/Toman conversion or mixing venues/currencies.
- No new real-time providers, broker credentials, investment recommendations,
  autonomous LLM agents, risk approval or order execution.
- Deterministic stages publish quality, descriptive technical, unavailable
  fundamentals/flow, risk and synthesis outputs. They are not autonomous agents.
- CI installs the optional Excel extra so workbook tests actually execute.
- TSETMC now requires literal OHLCV numeric fields and a source date; malformed or
  incomplete observations fail the complete call instead of being fabricated.
- Market-watch removes ambiguous `timestamp`, replacing it with
  `retrieved_at_utc` and nullable `source_timestamp`. Consumers must migrate.
  Daily history retains the pre-existing UTC date-label convention; it is not
  asserted to represent the exact exchange closing instant.

## Known limitations and remaining work

- A structurally valid file still has source trust UNVERIFIED. Even within an
  explicit age limit the risk gate remains UNASSESSED; stale/future blocks it.
- Age limits are owner-selected elapsed hours, not a verified exchange calendar.
- This is a one-shot local-inbox processor, not an installed scheduler or cloud
  watcher. Ready-file upload/atomic rename and scheduling are operator tasks.
- No Drive API access/read/write/sync is performed in this change. Files can be
  processed from an already-synchronized local folder. Reference-doc Drive sync
  remains NOT PERFORMED and requires selecting/authorizing a destination.
- Agents needing historical series, fundamentals or market flow must consume
  completed normalized data and supply separately verified inputs.
- Original input is preserved. No deletion or historical rewrite is performed.
- Crash leftovers in `.pending-*` are ignored; a stale lock requires operator
  verification before removal. Local output root must be trusted, not writable
  by untrusted users or shared with competing cloud writers.
