## روش و ایمنی

آرشیو با `zipfile` فقط از نظر فهرست، CRC، اندازه و مسیرها بررسی شد؛ 189 عضو داشت، `testzip()` خطایی گزارش نکرد و مسیر absolute یا `..` یافت نشد. محتوا در مسیر موقت جدا استخراج شد؛ فایل‌های `.git` و `.workspace` استخراج نشدند. هیچ اسکریپت، dependency، build یا برنامهٔ داخل آرشیو اجرا نشد و چیزی از آرشیو به‌صورت wholesale وارد مخزن نشد.

جست‌وجوی ایستای ساده برای الگوهای متداول secret، مقدار credential قابل استفاده پیدا نکرد؛ تنها ارجاع‌های متنی به متغیر محیطی `LOVABLE_API_KEY` دیده شد. این جست‌وجوی محدود، ممیزی امنیتی کامل محسوب نمی‌شود.

## یافته‌های ساختاری

ZIP یک برنامهٔ وب TypeScript/React مبتنی بر TanStack Start و Vite است؛ مخزن فعلی هستهٔ Python دارد. در میان 141 فایل عادی استخراج‌شده، تنها مسیرهای مشترک با مخزن فعلی `.gitignore`، `AGENTS.md` و `README.md` بودند. بنابراین این آرشیو نسخهٔ قابل جایگزینی/به‌روزرسانی مستقیم هستهٔ Python نیست؛ انتقال کامل آن، مهاجرت فناوری و تصمیم معماری جداگانه می‌خواهد.

گزارش `docs/architecture/AUDIT.md` داخل آرشیو تاریخ 2026-08-09 دارد و بخشی از ادعاهای آن با همان snapshot ضمیمه منطبق نیست: گزارش می‌گوید Provider واقعی، تست و لایهٔ یکپارچگی داده وجود ندارد، در حالی که آرشیو شامل `src/arya/providers/real-providers.ts`، `src/arya/core/data-envelope.ts` و تست‌های Vitest است. پس آن Audit برای snapshot فعلی، مرجع کامل و به‌روز نیست.

## ایدهٔ قابل استفاده

`src/arya/core/data-envelope.ts` یک الگوی مفید برای حمل `source`، `providerId`، timestamp، وضعیت‌های `LIVE`/`DEMO`/`STALE`/`UNAVAILABLE` و توضیح خطا دارد؛ تست‌های آن نیز برای DEMO، UNAVAILABLE و تازگی داده نمونه دارند. ایدهٔ عملی که به معماری Python فعلی منتقل شد، جلوگیری پیش‌فرض از اجرای تحلیل با Provider ساختگی است: کد فعلی Python در `configs/providers.yaml` برای crypto از `mock` استفاده می‌کند و در نبود guard می‌توانست خروجی تحلیل تولید کند.

## هشدارها دربارهٔ کد آرشیو

- `real-providers.ts` پس از پاسخ HTTP موفق، وضعیت را `LIVE` می‌گذارد؛ فراخوانی `envelope()` زمان محلی `Date.now()` را جای timestamp منبع می‌گذارد و freshness پاسخ را از timestamp بازار/ارائه‌دهنده نمی‌سنجد. بنابراین برچسب `LIVE` به‌تنهایی اثبات تازگی داده نیست.
- `real-symbols.ts` شناسه‌های TSETMC را به‌صورت ثابت نگه می‌دارد؛ برای نگاشت‌ها در همان فایل provenance، تاریخ تأیید یا تست تطبیق مستقل وجود ندارد. این mappingها برای استفادهٔ عملیاتی نیازمند راستی‌آزمایی رسمی‌اند.
- Provider بایننس و محتوای بازارهای خارج از بورس ایران با دامنهٔ جاری پروژه سازگار نیستند و منتقل نشدند.
- وجود `MOCK_META` و badge برای برخی پنل‌ها نشانهٔ مفیدی است، اما به معنی اثبات end-to-end بودن کل داده یا صحت سیگنال‌ها نیست؛ خود داده‌های ثابت و generator باید همچنان DEMO تلقی شوند.

## تغییر اعمال‌شده در هستهٔ فعلی

- `AryaApp` اکنون Provider غیرفعال را نمی‌پذیرد و در حالت عادی هر تحلیل/فهرست نماد متکی به driver=`mock` را با `MarketDataSafetyError` متوقف می‌کند.
- تنها آزمون‌های کنترل‌شده می‌توانند `allow_mock_data=True` را به‌صورت صریح به نمونهٔ برنامه بدهند؛ این گزینه به CLI اضافه نشده است.
- CLI خطای guard را با پیام روشن و exit code غیرصفر نشان می‌دهد.
- تست‌های جدید رفتار fail-closed و اولویت `enabled=false` را بررسی می‌کنند.

این safeguard فقط از استفادهٔ تصادفی از mock و Provider غیرفعال جلوگیری می‌کند؛ صحت نماد، مجوز استفاده، تازگی یا صحت Provider واقعی را تأیید نمی‌کند. آزمون‌های زندهٔ TSETMC و شکاف‌های NAV/CFI مستقل باقی می‌مانند و تا دریافت پاسخ معتبر همچنان نیازمند شواهدند.

## تصمیم‌های خارج از این تغییر

این بازبینی هیچ تصمیمی دربارهٔ تبدیل پروژه به وب‌اپ، جداکردن مخازن، فعال‌کردن crypto/forex/سهام خارجی، یا ساخت API جدید اتخاذ نمی‌کند. مواردی که به تصمیم مالک یا مستندات منبع رسمی نیاز دارند، در Change Record و رجیستری منابع جداگانه پیگیری می‌شوند.
